# Testing matrix

Generated by `make testing-matrix`. Don't edit it by hand.

For every attribute of every resource, this page names the acceptance tests that import it, change it and upgrade it. No test declares what it covers. The acceptance suite runs with a recorder around the provider, in process and in the built binary the CLI tests run, and the recorder writes down what each test made the provider do. CI runs the suite that way (`make testacc-matrix`) and fails when this page isn't what the run saw.

How to read a row:

- Import names the tests whose plan right after an import keeps the imported value of the attribute.
- Update names the tests that change the attribute in their configuration and plan the change in place. For an attribute that sometimes replaces, a test that plans a replacement for the change counts too, and the cell says which it saw.
- Upgrade names the tests that upgrade a state from an older schema version holding the attribute, and the directories of v0.1.0-rc.2's walkthrough that set it. The upgrade job applies those with v0.1.0-rc.2 and plans them with this build.
- gap means no test covers the cell yet. Each gap is a line in `internal/repocheck/testdata/testing-matrix-gaps.txt`. Once a test covers it, the check fails until the line goes.
- n/a means the cell can't happen. A computed attribute isn't set by configuration, one that always replaces has no update, and a write-only attribute is never stored.
- not in v0.1.0-rc.2 means that release's state schema snapshot doesn't hold the attribute, so no state it wrote does either.
